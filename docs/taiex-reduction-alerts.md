# 加權月線減碼提醒

依使用者提供的「台股策略回測總報告_減碼補回完整比較.xlsx」及確認：

- 20 日簡單移動平均包含當日收盤；以交易日計算，收盤嚴格低於均線才累計。
- 第 2 個連續交易日：LINE 預警，尚未觸發減碼。
- 第 3 個連續交易日：確認訊號，提醒下一交易日**收盤**將股票配置降至總資產 50%。
- 啟用時已在月線下方的舊走勢不補發。不新增2%門檻。必須先觀察到月線上方（或相等）的完成收盤，再開始新跌破的2／3日計數。
- 第 4 日及之後不重複叫使用者減半；收盤回到月線或以上後重新計數。
- 回補採附件3%→4.5%分批方案：自本輪策略預定減碼執行日開始追蹤最低收盤，創低則下修；反彈3%提醒下一交易日收盤配置補至75%，反彈4.5%補至100%。
- 同輪每個回補門檻只通知一次。若一天一次跳過兩門檻，合併為補至100%的卡片。第一批補回後再創低，更新同輪低點，但不重複第一批。
- 僅通知，不改動持股／成本／交易／績效。策略配置為假設依訊號於下一交易日收盤執行的追蹤狀態，不代表使用者真實成交。舊走勢沒有新減碼訊號時，不假設已減碼，也不捏造舊低點回補。

## 使用

管理員先在 `/web/admin/taiex-reduction` 選擇使用者，設定「核准並開啟」、「核准但暫停」或「停用並撤銷權限」。新使用者預設未核准。後台入口也加入既有管理員首頁。

已核准的使用者可在 LINE 私訊「減碼提醒開啟」。設定僅綁定該次訊息的 `event.source.user_id`；本人不能授予自己權限，不預設廣播給所有使用者或管理員。撤銷／本人關閉會在發送前重新檢查。
「減碼提醒」查本人訂閱狀態與最後完整檢查；「減碼提醒關閉」停止本人通知。
開啟時會排入背景檢查，非交易日／收盤前略過。遵守原有 LINE 每日推播總開關及使用者安靜時段。

管理頁提供「發送測試到我的 LINE」：僅登入管理員可按，POST 驗證既有 CSRF。接收人強制為目前管理員，不接受表單指定他人。測試訊息明確標示，使用獨立測試紀錄、固定 retry key，成功送出後間隔30秒即可重新手動測試，30秒內連點不重送；不需要等待交易日或收盤，也不會捏造市場訊號。

## LINE 卡片與名單內編輯

管理員在一對一聊天輸入「名單」或「使用者名單」，可分頁查看每人的月線權限與開關，點「編輯月線提醒」後直接核准／開啟、核准但暫停或撤銷權限。不必離開 LINE。保留「查看原本完整名單」入口（「名單詳情」），原有通知、靜音、活躍報告等文字管理指令保持原樣。

按鈕使用 LINE postback，目標綁定固定 user_id，避免用易變的名單編號修改別人。每次收到 postback 均重新確認事件發送者為管理員、來源為一對一聊天、目標仍在實際使用者名單、action／mode 為允許值；不相信卡片本身是授權憑證。拒絕群組／聊天室管理操作，避免名單外洩。

第2日預警採琥珀色、第3日確認採紅色，測試採深藍色標頭；Flex 卡片分開顯示狀態、2日／3日流程、真實收盤與均線及執行日期。測試卡不填入虛構指數。名單提供「測試新版卡片到我的 LINE」，或直接輸入「月線提醒測試」。新卡片測試使用 level=10（舊純文字測試為9），讓本日已做過文字測試者仍能驗收新卡片；成功送出30秒後可重新測試；連點或未知結果重試不重複推播。

新通知將完整 Flex JSON 存入原有 message TEXT 欄位後才送出；舊的未確認純文字紀錄仍保留原訊息格式，避免同一 retry key 在重試時更換內容。沒有資料庫遷移或新付費依賴。

## 資料庫與推播可靠性

第一次訂閱或執行背景工作時建立四個獨立資料表（`CREATE TABLE IF NOT EXISTS`）：

| 表 | 用途 |
|---|---|
| `taiex_reduction_subscriptions` | user_id 主鍵、核准權限、核准管理員、本人開關與更新時間 |
| `taiex_reduction_deliveries` | 訊號日＋user_id＋等級唯一鍵、固定訊息、固定 retry key、LINE 接受時間 |
| `taiex_reduction_user_state` | 每人獨立的起算日、已觀察跌破天數、本輪低點、回補階段、預定執行與當日可重試事件（JSONB） |
| `taiex_reduction_job_lock` | 全域有期限工作租約，跨實例且相容 Supabase transaction pooling |

不修改既有資料表。建立表格的 DB 權限若不足，回覆設定未確認／背景工作錯誤，不假裝成功。

發送前先持久化固定訊息與 UUID；失敗有限重試使用相同 `X-Line-Retry-Key`。HTTP 200，或帶已接受 request-id 的 409，才記錄 LINE 已接受；這不等同使用者已讀。未知結果不標完成，後續當日排程可重試原訊息。超過 23 小時不自動重試，避免 LINE 24 小時去重期限後造成重複。新提醒使用獨立 HTTP headers，不污染既有 LINE SDK 共用 client。每筆結果與租約均有 commit／rollback。

LINE 依既有官方帳號方案計算推播用量；不新增付費 API、Render 服務、依賴或全市場掃描。

## 新舊走勢與回補狀態

初次建立每人狀態時，以該人啟用時間之前最近一筆完成收盤為基準：收盤前啟用取前交易日，收盤後啟用可取當日。週末啟用以週五／最近交易日為基準。這可辨識啟用後第一個真實跌破，也不倒算啟用前已在月線下方的舊跌勢。

共享快照保留這次驗證過的近3個月 MA20 觀察列；個人狀態只保存最近3筆收盤及當輪低點與階段。排程漏日後，在完整歷史內順推策略狀態，只發當日新事件，不補發過期訊號。若歷史不足以銜接，清除無法驗證的舊週期，以當日重新觀察，不推測中間曾減碼或回補。關閉／未核准不發送，重新啟用仍須通過當日身分與權限檢查。

個人狀態與當日事件先 commit，再使用既有固定訊息／retry key 發送。重啟或同日重跑保留當日待送事件並由送達表去重。回補 level=30／45，原減碼 level=2／3，不更改舊送達紀錄。新表為獨立增量，可保留以回滾；回滾前先暫停本提醒，避免舊版邏輯重新計數。
