# 加權月線減碼提醒

依使用者提供的「台股策略回測總報告_減碼補回完整比較.xlsx」及確認：

- 20 日簡單移動平均包含當日收盤；以交易日計算，收盤嚴格低於均線才累計。
- 第 2 個連續交易日：LINE 預警，尚未觸發減碼。
- 第 3 個連續交易日：確認訊號，提醒下一交易日**收盤**將股票配置降至總資產 50%。
- 第 4 日及之後不重複叫使用者減半；收盤回到月線或以上後重新計數。
- 僅通知，不改動持股／成本／交易／績效。附件提供多種補回方案，本次未選定，沒有自動新增補回規則。

## 使用

管理員先在 `/web/admin/taiex-reduction` 選擇使用者，設定「核准並開啟」、「核准但暫停」或「停用並撤銷權限」。新使用者預設未核准。後台入口也加入既有管理員首頁。

已核准的使用者可在 LINE 私訊「減碼提醒開啟」。設定僅綁定該次訊息的 `event.source.user_id`；本人不能授予自己權限，不預設廣播給所有使用者或管理員。撤銷／本人關閉會在發送前重新檢查。
「減碼提醒」查本人訂閱狀態與最後完整檢查；「減碼提醒關閉」停止本人通知。
開啟時會排入背景檢查，非交易日／收盤前略過。遵守原有 LINE 每日推播總開關及使用者安靜時段。

管理頁提供「發送測試到我的 LINE」：僅登入管理員可按，POST 驗證既有 CSRF。接收人強制為目前管理員，不接受表單指定他人。測試訊息明確標示，使用獨立 level=9 紀錄、固定 retry key，每個台灣日期最多被 LINE 接受一次；不需要等待交易日或收盤，也不會捏造市場訊號。

## 資料庫與推播可靠性

第一次訂閱或執行背景工作時建立三個獨立資料表（`CREATE TABLE IF NOT EXISTS`）：

| 表 | 用途 |
|---|---|
| `taiex_reduction_subscriptions` | user_id 主鍵、核准權限、核准管理員、本人開關與更新時間 |
| `taiex_reduction_deliveries` | 訊號日＋user_id＋等級唯一鍵、固定訊息、固定 retry key、LINE 接受時間 |
| `taiex_reduction_job_lock` | 全域有期限工作租約，跨實例且相容 Supabase transaction pooling |

不修改既有資料表。建立表格的 DB 權限若不足，回覆設定未確認／背景工作錯誤，不假裝成功。

發送前先持久化固定訊息與 UUID；失敗有限重試使用相同 `X-Line-Retry-Key`。HTTP 200，或帶已接受 request-id 的 409，才記錄 LINE 已接受；這不等同使用者已讀。未知結果不標完成，後續當日排程可重試原訊息。超過 23 小時不自動重試，避免 LINE 24 小時去重期限後造成重複。新提醒使用獨立 HTTP headers，不污染既有 LINE SDK 共用 client。每筆結果與租約均有 commit／rollback。

LINE 依既有官方帳號方案計算推播用量；不新增付費 API、Render 服務、依賴或全市場掃描。
