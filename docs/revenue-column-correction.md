# 營收欄位與估值連動資料更正

根因：MOPS HTML 累計年增率標題是「前期比較增減(%)」。舊程式找「累計營收增減」失敗後取固定第六欄，讀到「上月比較增減」；月增率又被存入 revenue_history 的 cum_yoy_pct。月增欄本身也誤取單月年增。11/11 正式日誌顯示修補拿到 2383=13.65%、2308=14.16%，與錯誤欄位完全一致。

官方 11510 列：2383 月增13.65%、單月年增203.07%、累計年增114.05%；2308 月增14.16%、單月年增30.11%、累計年增36.31%。舊資料可重現台光電營收11／估值2，正確資料沿原公式為營收20／估值12。台達電沿本次官方 PE38.29 試算為營收17／估值13；正式驗證另外列出實際估值快照來源日，不把不同日期混為同日報價。

修正：revenue_parser.py 的 HTML／CSV 只依完整欄名及明列別名讀取，不猜位置。累計百分比與同列今年／去年累計金額交叉驗證（容忍官方百分比小數顯示差）；缺百分比可由同列累計金額計算，兩者都無則保留缺值；欄名歧義、非有限值、矛盾資料拒絕。官方負月營收可如實保留，不擅自改成零。

五個原有營收、估值及類別模型函式與 origin/main 逐段比較相同，不調權重或評分門檻。

修復程序：GitHub 限定 OIDC 工作先取得既有月份計畫（最多近24期），在 Render 外抓 MOPS 上市／上櫃／興櫃官方表，三個市場齊備後逐月送入。最新完整月份更新正式月營收快照；歷史月份只更正已存在資料，不任意建立整個市場的歷史。原值和月營收快照先備份至既有 shared_data_snapshots，鍵 revenue_repair_v2_backup:<民國年月>。備份與更正同一資料庫交易，失敗全數 rollback，同批重跑不覆蓋備份。工作互斥；成功回覆只在 commit 後。沒有 schema 遷移、沒有使用者交易／持股／watchlist_scores 寫入。

修復後清除月營收記憶體與共享快取，查詢直接重算；保留舊歷史評分作為當時曾顯示內容，不事後偽造。近七日 LINE 分數與營收明細會標示「資料更正」，避免把分數回升解讀成公司基本面突然改善。新評分也提供營收月份。

測試：真實三市場11510表解析成功；30項解析、欄位換序、數值驗證、原公式重現、交易原子性、回滾、重試、未授權、部分市場不發布、LINE與既有工作簽章回歸通過。正式更正須另外核對 Actions 完成結果。

回滾：優先回滾應用變更並保留已核對的正確公開財務值；不因應用回滾而重新污染資料。若必須回復資料，先停用此 workflow，於交易中讀取對應 backup 的 before（欄序 code,period,yoy,cum_yoy,mom,month_revenue）恢復原列，僅移除 inserted_codes 於該民國年月的新列，必要時依 monthly_snapshot 還原當時快照；確認目前快照仍為同月份後才還原，避免覆寫更新月份。保留備份，清除記憶體快取或重啟後核對。不要把本次修復當作可回溯更改真實歷史績效的授權。
